# 风险登记册

> 版本：0.1
> 状态：持续维护
> 范围：本地 Agent 平台的产品、技术、数据安全、AI 协作和交付风险。

## 风险状态

- Open：已识别，尚未完全缓解。
- Mitigating：已有缓解措施，仍需跟踪。
- Accepted：已知风险，当前阶段接受。
- Closed：已解决或不再适用。

## 风险清单

| ID | 风险 | 影响 | 触发信号 | 缓解措施 | 状态 |
|---|---|---|---|---|---|
| R-001 | 权限模型设计错误导致知识库泄漏 | 用户看到不该看的资料，破坏本地安全信任 | 有 Agent 权限但无知识库权限时仍能检索；导出引用未授权资料 | 知识库权限优先；权限测试强制；导出前展示来源；审计记录 | Open |
| R-002 | Agent prompt 或业务逻辑散落在应用代码里 | 后续无法版本化、评测和复用 Agent | prompt 写在 route/component 中；同类逻辑复制多份 | 统一 Agent 包结构；manifest/schema/workflow/prompt 分离；准入检查 | Open |
| R-003 | AI 执行 Agent 过度重构或扩大范围 | 引入隐藏回归，难以 review 和回滚 | 单个任务 diff 很大；无关文件被修改；格式化混入业务改动 | 任务卡限制修改范围；小 PR；主线程 review；禁止无关重构 | Open |
| R-004 | 缺少测试导致功能看似完成但不可验证 | 质量不稳定，用户试用失败 | 完成汇报只有描述，没有命令和结果 | 测试优先门禁；任务必须列测试用例；关键路径自动化 | Open |
| R-005 | RAG 质量差导致方案胡写或引用错误 | 用户不信任输出，方案不可用 | 引用与内容不对应；资料不足仍强行生成 | 固定测试文档集；引用校验；来源/推断/需确认三类标记 | Open |
| R-006 | 审计日志不完整 | 无法追溯谁用了什么资料生成了什么 | task run 没记录 knowledge base、prompt、输出或导出 | 建立统一 Task Run/Audit Event；权限和导出走统一服务 | Open |
| R-007 | 本地部署复杂，非技术用户无法安装使用 | 产品无法交付给小团队 | 依赖过多；配置步骤多；出错难诊断 | Docker Compose；管理员向导；连接测试；部署文档 | Open |
| R-008 | 模型能力不足导致体验不稳定 | 弱模型无法完成复杂方案生成 | 长 prompt 失败；输出结构不稳定；JSON 经常坏 | 拆步骤；schema 校验；重试；人工确认；eval 回归 | Open |
| R-009 | 数据库 schema 频繁变化破坏历史数据 | 升级困难，试用数据丢失 | migration 不可回滚；表结构频繁推翻 | ADR 记录；migration 审查；开发期可重建，试用期前制定备份 | Open |
| R-010 | 重复造轮子拖慢进度 | 时间浪费在低差异化基础设施 | 自研 parser、vector db、auth、workflow engine | 每个大功能先做复用调研；记录选型理由和 license | Open |
| R-011 | Agent 质量无法持续改进 | 定制经验无法形成复利 | 失败只改 prompt，不沉淀样例 | 失败案例进入 eval；Agent changelog；定制到通用流程 | Open |
| R-012 | Git 工作流混乱导致难以回滚 | main 不稳定，无法定位问题 | 巨型提交；多个 Agent 同时改同一区域 | 独立分支；小任务；清晰提交；阶段 tag；主线程协调 | Open |

## 维护规则

- 每个阶段开始前复查本表。
- 新发现的高风险必须当天登记。
- 每个风险至少有触发信号和缓解措施。
- 关闭风险必须说明原因或证据。
- 权限、审计、数据、导出、模型网关和 Agent 包规范相关风险优先处理。
